# Audit CMS dan arsitektur halaman Pengembang

**Tanggal pemeriksaan source:** 3 November 2026  
**Basis pemeriksaan:** arsip proyek `astro.zip`, source Astro/TypeScript/JavaScript, SQL migrations, workflow CI, dan dokumentasi proyek.  
**Jenis audit:** static code and configuration review. Ini bukan penetration test dan bukan verifikasi instance Supabase/Cloudflare yang sedang berjalan.

## 1. Ringkasan eksekutif

CMS sudah memiliki fondasi keamanan yang cukup baik untuk proyek kelas: endpoint admin memeriksa sesi, mutasi memeriksa origin, cookie sesi memakai `HttpOnly` dan `SameSite=Strict`, login dibatasi melalui tabel database, body JSON dibatasi saat stream dibaca, upload media memeriksa signature file, dan sejumlah operasi penting memakai PostgreSQL RPC transaksional. RLS aktif pada tabel CMS yang dibuat oleh migration dan akses aplikasi berjalan melalui server-side service-role client. Tidak ditemukan service-role key yang ditanam pada script browser dalam source yang diperiksa.

Temuan audit terpenting bukan bypass autentikasi yang terbukti, melainkan **konsistensi transaksi, kehilangan perubahan saat ada penyimpanan bersamaan, serta cakupan revisi/audit yang belum merata**. Dua masalah mendapat perbaikan source dan migration dalam paket ini: pengaturan global kini menggunakan patch merge di dalam transaksi/lock, dan pengunggahan aset global membuat snapshot serta audit log dalam transaksi yang sama. Perbaikan ini belum aktif di database sampai migration Stage 4 diterapkan.

Halaman `/pengembang` juga telah dipisahkan secara visual dan runtime dari layout global website. Data tetap berasal dari Supabase dan `site_pages` yang sama. Dengan demikian halaman berdiri sendiri dari sisi layout, CSS, JavaScript, dan aset global, tetapi tidak menduplikasi data, autentikasi, atau database.

**Status keseluruhan:** dasar arsitektur layak dilanjutkan ke Preview setelah migration Stage 4 diterapkan. Belum layak disebut terverifikasi production sebelum build CI, SQL migration, autentikasi, Storage, dan alur CMS diuji pada environment Preview nyata.

## 2. Ruang lingkup pemeriksaan

Pemeriksaan mencakup: `src/pages/pengembang.astro`, layout dan script halaman baru, `src/lib/data.ts`, `src/lib/admin-auth.ts`, `src/lib/cms-admin.ts`, `src/lib/media-validation.ts`, middleware, seluruh endpoint `src/pages/api/admin/`, halaman dashboard admin, SQL migration CMS/Stage 3/Stage 4, tiga unit-test file, konfigurasi package, GitHub Actions workflow, dan dokumentasi CMS.

Tidak tersedia dalam arsip: kredensial Supabase/Cloudflare, status migration pada database aktif, konfigurasi policy bucket Storage, environment variables deployment, log Worker, atau URL Preview untuk pengujian.

## 3. Halaman `/pengembang`: perubahan dan batas kemandirian

### Yang dipisahkan

- `src/layouts/DeveloperLayout.astro` menjadi layout mandiri dengan head metadata, canonical, Open Graph, Twitter card, JSON-LD ProfilePage, banner preview, skip link, dan pemuatan stylesheet/script khusus.
- `src/styles/developer-portfolio.css` memuat gaya visual editorial/brutalist dari draft, tanpa memuat stylesheet global website.
- `src/scripts/developer-portfolio.js` menangani navigasi panel, drawer, jam WIB, scroll progress, reveal, skill count-up, carousel kutipan, typing effect, efek interaksi, dan salin kontak.
- Tidak memakai `Layout.astro`, `Header`, `Footer`, tema global, canvas jaringan, widget offline, audio iframe, GlobalClock, atau script `utama.js`. Tidak mengimpor komponen global yang membawa efek samping halaman lain.
- Query halaman tidak lagi melalui `getPageContext()`/`getSiteData()` yang mengambil beberapa dataset website sekaligus. Route mengambil pengaturan, anggota, foto galeri fallback, SEO, konten, dan section yang memang dibutuhkan halaman ini.

### Data yang tetap terhubung

- Identitas dan skill yang memang tersimpan pada data anggota tetap dibaca dari tabel anggota. Data struktur organisasi tetap menjadi prioritas untuk jabatan profil, sesuai perilaku halaman lama.
- Konten lama `site_pages.content` tetap digunakan: `role`, `eyebrow`, `headline`, `intro`, `devIntroText`, `taglines`, `experiences`, dan `quote`.
- Data draft editorial disusun dalam namespace `developer.*`, sehingga tidak menghapus field lama dan dapat dikelola melalui modul SEO/konten halaman.
- Pengaturan kelas/media sosial tetap memakai `site_settings`; sosial personal tetap berasal dari data anggota. Kunci `website` ditambahkan pada allowlist sosial karena halaman lama menampilkan tautan itu.
- Kontrol section `/pengembang` kini dipisah menjadi sepuluh key: `profile`, `skills`, `work`, `motivation`, `contact`, `philosophy`, `experience`, `quotes`, `education`, `notes`. Key `story` lama tetap menjadi fallback untuk `profile`, bukan sakelar yang mematikan seluruh `<main>`.
- Konten teks dirender sebagai teks Astro biasa, bukan HTML mentah. URL gambar/tautan dinormalisasi berdasarkan protokol yang diizinkan. Persentase skill dibatasi 0–100 saat render dan diberi keterangan bahwa itu penilaian reflektif, bukan sertifikasi.

### Batas yang masih ada

- CMS dapat mengubah konten dan status section yang sudah dipetakan, tetapi tidak dapat membuat section/komponen visual baru. Perubahan susunan markup atau desain tetap memerlukan source code.
- Editor konten Pengembang masih berupa JSON textarea pada modul SEO. Belum ada form visual khusus untuk tiap array proyek, skill, timeline, kutipan, edukasi, notes, dan kontak.
- Route masih merupakan bagian dari aplikasi Astro/Cloudflare yang sama dan tetap bergantung pada koneksi data Supabase. “Berdiri sendiri” tidak berarti menjadi deployment atau sistem database terpisah.

## 4. Kontrol keamanan yang sudah ditemukan

| Area | Kontrol dalam source | Catatan audit |
|---|---|---|
| Sesi admin | HMAC-SHA256, TTL 8 jam, signature constant-time, cookie `HttpOnly`, `SameSite=Strict`, `Secure` pada production | Tidak ada sistem user/role individual atau revokasi sesi per perangkat |
| Mutasi admin | Mutasi menolak request tanpa Origin yang sama dengan URL aplikasi | GET/HEAD/OPTIONS tetap memerlukan sesi melalui `isAdminRequest` |
| Login | Batas lima percobaan per 5 menit melalui RPC Supabase; IP disimpan sebagai HMAC, bukan teks mentah | Memerlukan Cloudflare `CF-Connecting-IP` pada production; gagal tertutup jika tidak ada |
| Request body | Helper membaca stream dan menegakkan byte limit, bukan hanya mempercayai Content-Length | Setiap endpoint menetapkan batas sendiri |
| Upload | Pemeriksaan magic bytes, MIME dari allowlist, SVG/HTML/script ditolak, batas file 20 MB dan body 22 MB | Masih ada risiko konsumsi memori dan konsistensi lintas Storage/DB |
| Referensi media | Path traversal ditolak; penghapusan menelusuri anggota, galeri, settings, pages, drafts, revisions dan gagal tertutup jika scan gagal/terpotong | Pemeriksaan dan delete tidak berada dalam satu transaksi lintas layanan |
| Database | RLS diaktifkan pada tabel CMS; RPC transaksional memakai `SECURITY DEFINER`, search_path dipatok, execute diberikan ke service_role | Harus diverifikasi pada database aktif, tidak hanya migration file |
| Preview | Draft hanya dibaca ketika cookie admin valid; response no-store/noindex dan bypass service worker | Perlu uji browser dengan sesi yang sama |
| Header | `nosniff`, Referrer-Policy, Permissions-Policy, frame protection, CSP, cache control admin | CSP masih mengizinkan inline script/style dan HTTP image/media; HSTS tidak ditetapkan di file ini |

## 5. Temuan audit berdasarkan prioritas

### P1 — Prioritas tinggi

**P1-01. Penggantian koleksi dan navigasi belum atomik.**  
File: `src/pages/api/admin/collections.ts`, `src/pages/api/admin/navigation.ts`.  
Kedua endpoint membaca data lama, melakukan `upsert`, lalu menghapus row satu per satu. Kegagalan delete kini dilaporkan ke client, tetapi data hasil upsert sudah terlanjur commit. Hasilnya dapat menjadi keadaan campuran, bukan rollback total. Operasi ini juga belum masuk satu RPC revisi/transaksi. Rekomendasi: pindahkan replace/upsert/delete ke satu RPC PostgreSQL per entitas, validasi seluruh payload di server, buat snapshot/audit di transaksi yang sama, lalu balas sukses hanya sesudah transaksi commit.

### P2 — Perlu diperbaiki untuk ketahanan dan operasional

**P2-01. Workflow draft/publish tidak mencakup semua modul CMS.**  
Draft/publish hanya untuk `site_pages` (SEO dan konten halaman). Anggota, galeri, guru, skills, navigasi, section, pengaturan global, dan media masih ditulis langsung. Salah edit pada modul tersebut tidak dapat dipulihkan lewat workflow draft. Riwayat saat ini paling lengkap untuk page content dan global settings, bukan seluruh tabel. Rekomendasi: buat perubahan bertahap, dengan audit snapshot/soft-delete untuk data kritis dan staging/publish untuk modul yang memang membutuhkan review.

**P2-02. Audit log untuk beberapa mutasi masih best-effort.**  
`logCmsAction()` kini mencatat kegagalan ke server log, tetapi tidak membatalkan mutasi atau mengubah respons sukses. Maka data dapat tersimpan tanpa baris `admin_audit_logs`. Jalur RPC penting mencatat log di transaksi yang sama; endpoint CRUD langsung belum konsisten. Rekomendasi: masukkan audit insert dalam RPC transaksi untuk operasi yang harus dapat diaudit.

**P2-03. Operasi Supabase Storage dan PostgreSQL tidak dapat menjadi satu transaksi.**  
Upload dapat menyimpan object Storage sebelum row metadata atau record galeri/anggota tersimpan. Ada cleanup best-effort; jika cleanup gagal, orphan object dapat tertinggal. Ketika delete file Storage sukses tetapi delete row metadata gagal, metadata yatim tertinggal. Pemeriksaan referensi juga terpisah dari delete; referensi baru yang dibuat bersamaan setelah scan selesai berpotensi luput (time-of-check to time-of-use). Rekomendasi: gunakan status/queue operasi media (`pending`, `active`, `cleanup_required`), retry cleanup idempoten, dan laporan orphan untuk rekonsiliasi.

**P2-04. Upload multipart membuat beberapa representasi file di memori.**  
Endpoint membaca body sampai 22 MB, membuat Request baru untuk `formData()`, lalu membuat Buffer untuk upload. Dalam runtime Worker, peak memory dapat lebih besar daripada ukuran file yang diizinkan, terutama bila ada thumbnail. Rekomendasi: evaluasi streaming upload langsung ke Storage atau turunkan batas file/body; ukur pada Worker Preview, bukan hanya desktop.

**P2-05. Media Library melakukan scan Storage rekursif sampai 10.000 entri pada request.**  
Hasil kemudian dikirim sebagai satu array ke browser. Pembatas mencegah scan tanpa batas, namun waktu, penggunaan memori, dan payload akan tumbuh seiring perpustakaan media. Rekomendasi: cursor pagination pada API dan UI, filter server-side, serta simpan indeks `media_assets` sebagai sumber daftar utama; scan Storage hanya sebagai proses rekonsiliasi terpisah.

**P2-06. Sesi admin tidak individual dan tidak dapat dicabut per perangkat.**  
Satu `ADMIN_PASSWORD` dan satu secret digunakan bersama. Cookie stateless berlaku sampai delapan jam; rotasi secret mencabut semua sesi, tetapi tidak ada tombol revoke satu sesi, multi-admin, MFA, atau identitas pelaku. Rekomendasi: jika CMS dipakai beberapa operator, pindah ke identitas per-user dengan role, MFA/SSO, session ID tersimpan dan revokasi. Untuk penggunaan satu operator, lindungi password/secret dan aktifkan WAF rate-limit Cloudflare.

**P2-07. CSP belum memakai nonce/hash dan belum memaksa HTTPS untuk semua konten.**  
CSP memakai `script-src 'self' 'unsafe-inline'`, `style-src 'unsafe-inline'`, serta `img-src`/`media-src` mengizinkan `http:`. Ini masih memberi perlindungan dasar, tetapi tidak setara CSP ketat. HSTS tidak didefinisikan pada `_headers`. Rekomendasi: audit semua inline script/style dan dependency, migrasikan ke nonce/hash atau asset bundling, hapus HTTP bila seluruh media sudah HTTPS, lalu set HSTS pada domain production setelah HTTPS dikonfirmasi. Jangan mengubah CSP secara membabi-buta sebelum menguji Preview karena dapat memblokir aplikasi.

**P2-08. Konfigurasi bucket Storage belum dapat diverifikasi dari source.**  
Aplikasi memakai `getPublicUrl`, sehingga alur publik mengasumsikan bucket dapat diakses secara publik. Perlu verifikasi bucket `astro`, policy upload/delete, dan apakah objek sensitif (misalnya dokumen) berada di bucket yang sama. Jangan menyimpan berkas privat dalam bucket publik; pisahkan bucket privat dan signed URL bila diperlukan.

### P3 — Peningkatan kualitas dan pemeliharaan

**P3-01. Editor konten Pengembang masih JSON mentah dan belum memiliki schema khusus di server.**  
JSON memberi fleksibilitas, tetapi rawan typo, struktur salah, dan sulit digunakan di layar ponsel. Render saat ini menormalisasi sebagian field/array sebagai pertahanan tambahan, tetapi API konten belum memvalidasi bentuk setiap grup `developer.*` secara ketat. Rekomendasi: form visual per grup (`profile`, `skills`, `projects`, `timeline`, `contacts`), schema validation di server, serta tombol tambah/urutkan/hapus array. Pertahankan JSON advanced mode sebagai fallback.

**P3-02. Belum ada `package-lock.json`.**  
Dependensi utama dipatok versinya di `package.json`, tetapi dependensi transitif belum sepenuhnya reproducible. CI memakai `npm install`, bukan `npm ci`. Rekomendasi: buat dan commit lockfile menggunakan Node versi proyek, lalu gunakan `npm ci` pada CI.

**P3-03. Cakupan tes otomatis belum menutup alur CMS.**  
Tiga file test saat ini fokus pada autentikasi, helper CMS, dan validasi media. Belum ada route integration test, SQL migration test, preview/cache test, concurrency test, atau E2E browser untuk seluruh dashboard. Rekomendasi: tambah test untuk operasi atomik navigasi/koleksi, workflow modul non-page, concurrent settings patch, permission matrix, upload cleanup, dan draft publish.

**P3-04. Restore backup adalah upsert, bukan mirror penuh.**  
Baris yang tidak ada dalam file backup sengaja tidak dihapus. Backup JSON juga tidak menyertakan binary Storage. Perilaku tersebut sudah dicatat dalam dokumentasi, tetapi label UI dan prosedur restore harus terus menyebutnya sebagai merge/upsert, bukan pemulihan identik. Untuk disaster recovery, backup database penuh dan Storage tetap diperlukan.

## 6. Perbaikan yang sudah disertakan dalam source paket ini

1. Route `/pengembang` dipindahkan ke `DeveloperLayout.astro` dan stylesheet/script khusus.
2. Konten draft editorial digabungkan dengan konten dan sumber data lama, termasuk data organisasi, profil anggota, stack proyek website kelas, perjalanan belajar, prinsip, pengalaman, kutipan, dan media sosial.
3. Sepuluh section Pengembang memiliki toggle sendiri; `story` menjadi kompatibilitas/fallback profil, tidak lagi menyembunyikan seluruh halaman.
4. `website` ditambahkan ke allowlist sosial agar link website yang didukung halaman lama bisa disimpan lewat CMS; unit test ditambahkan.
5. Endpoint section menolak key duplikat, label kosong, dan sort order yang tidak wajar.
6. Endpoint navigasi/koleksi menolak duplikasi dan tidak lagi menyamarkan kegagalan delete; namun P1-01 tetap belum selesai karena seluruh operasi belum atomik.
7. Kegagalan insert audit helper kini muncul di log server, tidak ditelan diam-diam.
8. Pengaturan global memakai RPC patch merge di bawah advisory lock bersama asset global. Ini mengurangi risiko lost update saat dua penyimpanan bersamaan.
9. Upload aset global menggunakan RPC yang mencatat pengaturan, snapshot revisi, dan audit log di transaksi database.
10. Dokumentasi CMS diperbarui untuk layout mandiri, schema `developer.*`, urutan migration, workflow, dan batas editor JSON.

## 9. Batas verifikasi pada paket ini

Paket ini diperiksa melalui pembacaan source dan pemeriksaan statis. Pemeriksaan yang berhasil: syntax JavaScript seluruh file yang ditemukan, transpile syntax 30 file TypeScript dan frontmatter Astro tanpa diagnostic syntax, parsing 5 file JSON, parsing CSS portofolio, pemeriksaan seluruh relative import, serta konsistensi 10 section antara halaman, allowlist endpoint, dan migration. Pemeriksaan TypeScript tersebut bukan type-check penuh dan bukan validasi template oleh compiler Astro.

Lingkungan pemeriksaan menggunakan Node `v22.16.0`, sedangkan proyek menetapkan Node `>=22.23.4` dan `.nvmrc` `24.22.1`. `node_modules` dan lockfile tidak tersedia, sehingga `astro check`, Vitest, build Astro, dan `npm audit` tidak dapat dinyatakan lulus dari pemeriksaan ini. `psql` juga tidak tersedia, dan tidak ada koneksi ke Supabase production, maka syntax/permission/transaction migration belum diuji dengan PostgreSQL nyata. Arsip tidak menyertakan environment secrets, sehingga login, Storage, RLS aktual, dan Cloudflare Worker belum diuji runtime.

**Kesimpulan verifikasi:** source sudah dipersiapkan dan temuan statis penting ditangani sebagian; jangan deploy langsung ke production tanpa menerapkan Stage 4 di Preview dan menjalankan daftar uji di atas.
